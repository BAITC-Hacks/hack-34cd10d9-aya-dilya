# Firebird: механизм подбора и подключение интерфейса

Сервис загружает 66 профилей, применяет ограничения запроса и возвращает до
трёх карточек с объяснениями на русском. Работает локально без ключей,
сети, внешней модели и базы данных. Это реализация участника A. Дополнительно доступен серверный OpenAI-редактор объяснений; основной подбор от него не зависит.

Новые возможности и инструкция для участника B: [умный подбор, AI и «План Б»](smart-matching.md).

## Быстрый запуск

Нужны Node.js 20.19+ в ветке 20.x или Node.js 22.12+ и npm.
Проверено на Node.js 20.20.0, npm 10.8.2, macOS.

```sh
npm ci
npm run check
npm run demo
```

`check` проверяет актуальность подготовленных данных, TypeScript, тесты
и сборку сервиса в браузерный ES-модуль. `demo` печатает восемь проверенных
запросов, карточки, причины пустых результатов и измеренное время работы.

Стек интерфейса в каркасе: React + TypeScript + Vite. `npm run dev`,
`npm run build` и `npm run preview` предназначены для приложения участника B.
Интерфейс MVP уже подключён в базовой ветке. Новые поля пожеланий, источников и альтернатив нужно подключить участнику B по инструкции выше.

## Подключение для участника B

Общий контракт находится в `src/shared/contracts.ts`, публичные функции —
в `src/core/index.ts`. Контракт первоначального коммита `00aee3b` сохранён.
Можно заменить тестовый адаптер готовым объектом `recommendationService`.

```ts
import {
  getCatalogOptions,
  recommend,
  RequestValidationError,
  RecommendationServiceError,
} from "./core"; // пример для файла непосредственно в src/

const options = getCatalogOptions();
// options: cities, categories, eventFormats, languages,
//          dateRange: { min: "2026-09-23", max: "2026-12-31" }

try {
  const result = await recommend({
    city: "Алматы",
    date: "2026-10-04",
    eventFormat: "корпоратив",
    category: "Ведущий",
    budgetKzt: 2_000_000,
    // language: "русский",
    // durationHours: 6,
  });
  console.log(result.status, result.summary, result.cards);
} catch (error) {
  if (error instanceof RequestValidationError) {
    console.log(error.code, error.issues); // field + message для полей формы
  } else if (error instanceof RecommendationServiceError) {
    console.log(error.code, error.message); // отдельная техническая ошибка
  } else {
    throw error;
  }
}
```

`getCatalogOptions()` синхронный и возвращает новую копию справочников.
При невозможности загрузить каталог он может выбросить техническую ошибку.
`recommend()` всегда возвращает Promise. Для отсутствующих необязательных
полей используйте отсутствие свойства или `undefined`, не `null` и не `""`.
Бюджет и длительность передавайте числами, не строками из HTML input.

### Результаты и ошибки

| Результат | Значение | Карточки |
| --- | --- | --- |
| `matched` | Есть кандидаты, удовлетворяющие всем условиям | 1–3 |
| `category_absent` | В каталоге указанного города нет категории | 0 |
| `no_match` | Категория есть, все кандидаты исключены условиями | 0 |
| `INVALID_REQUEST` | Promise отклонён с `RequestValidationError` | Не бизнес-результат |
| `SERVICE_ERROR` | Техническая ошибка, `RecommendationServiceError` | Не бизнес-результат |

`summary` нужно показывать во всех трёх бизнес-состояниях, включая успешную
выдачу. `explanation` — готовый текст карточки. Не повторяйте фильтры и
ранжирование в компонентах. Не заменяйте ошибку сервиса пустым массивом.
Когда пользователь быстро меняет параметры, устаревший асинхронный ответ
не должен перезаписывать результат последнего запроса.

`availability: not_busy_in_dataset` означает «по календарю не занят»,
а не подтверждённую бронь. Показывайте цену с «от» и флаги `synthetic`,
`cityImputed`, `priceImputed`. `synthetic=false` не означает проверку сервисом.
`Зарубежье` сохранено как исходное значение поля city, а не конкретный город.

## Данные и воспроизводимость

`src/data/raw/contractors.csv` — побайтовая копия пользовательского CSV.
CSV-парсер работает только при подготовке данных и в тестах; в браузере
используется подготовленный `src/data/catalog.json`.

```sh
npm run data:prepare  # воспроизвести catalog.json и audit.json из исходного CSV
npm run data:check    # проверить, что подготовленные файлы не устарели
```

`6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d`.

| Показатель | Значение |
| --- | ---: |
| Уникальных профилей | 66 |
| Алматы / Астана / Зарубежье | 50 / 15 / 1 |
| Отдельных категорий | 17 |
| Синтетических профилей | 13 |
| Город заполнен при подготовке | 8 |
| Цена заполнена при подготовке | 18 |

Полный аудит по категориям находится в `src/data/audit.json`. Категории
многозначные, поэтому их суммы не равны количеству людей и организаций.
Описания сохранены полностью. Новых профилей в продуктовый каталог не добавлено.
Синтетические записи в unit-тестах изолированы в `tests/core/fixtures.ts`.

Загрузчик использует CSV-парсер с поддержкой кавычек, запятых и переносов
внутри ячеек. Списки разделяются по `|`; `True` и `False` явно преобразуются
в boolean. Пустой `max_hours` становится `null`, пустой `busy_dates` — `[]`.
Дубликаты id, некорректные флаги, цены, даты и структура CSV вызывают ошибку,
не молчаливую потерю записей. Скрипт подготовки также проверяет размер каталога.

## Правила подбора

Пайплайн: подготовленный каталог → проверка запроса → город и категория →
обязательные ограничения → число подтверждённых тем пожеланий → начальная цена/id → первые три → объяснения.

1. Город совпадает с city, категория входит в categories. Переезды в другой
   город из description не меняют область поиска. Сравнение меток игнорирует
   регистр и лишние пробелы; транслитерацию и синонимы не угадывает.
2. Дата — существующая календарная строка YYYY-MM-DD внутри включительного
   диапазона 23.09–31.12.2026. Вне окна данных отсутствие записи о занятости
   нельзя интерпретировать как доступность, поэтому запрос отклоняется.
3. Исключаются busy_dates, price_from_kzt > budgetKzt, отсутствие формата,
   указанного языка и недостаточная указанная длительность.
4. `max_hours=null` означает, что ограничение присутствия неприменимо.
   Никакие параметры не ослабляются автоматически. Площадки проходят
   те же проверки, что и остальные подрядчики.
5. Бюджет — целое неотрицательное число тенге за одного подрядчика и одно
   мероприятие. Нулевой бюджет валиден и обычно даёт пустую выдачу.
   Длительность — положительное конечное число, допускаются дробные часы.
6. Бюджет и длительность проверяются включительно. Бюджет 100 000 подходит
   для цены «от 100 000», запрос 6 часов подходит для max_hours=6.

Непустые неизвестные город/категория трактуются как отсутствие в каталоге,
неизвестные формат/язык — как неподдерживаемые условия. UI должен использовать
справочники. Пустые строки, null, неверные типы и даты — ошибки ввода.

### Ранжирование

После обязательных фильтров при наличии `preferences` сначала сортируем по числу тем с цитатами из описания (по убыванию), затем по `(priceFromKzt ASC, id ASC)`. Без пожеланий сохраняется прежний порядок по цене/id.
Сравнение id посимвольное и не зависит от локали; порядок исходных строк
не влияет на выдачу. Сначала предлагается меньшая начальная цена.
Это прозрачная базовая политика, а не предсказание качества или итоговой
сметы. Никаких случайных факторов, внешней модели и повторного ранжирования
на стороне UI нет. Флаги происхождения данных не дают штрафов или бонусов.

При равных признаках дополнительных данных для оценки качества нет.
Детерминированный id разрешает равенство; система не придумывает различия.

### Объяснения и пустая выдача

Карточка содержит факты совпадения с запросом: формат, начальную цену и
бюджет, календарь, а также язык/длительность, если они указаны. Вторая часть
может содержать дословный фрагмент description длиной до 180 символов.
Фрагмент выбирается по простым фиксированным текстовым признакам; рекламные
обещания отсекаются эвристикой. Если информативного фрагмента нет, используются
языки и длительность из структурированных полей. Эвристика не является LLM.

Цитата помечена как описание профиля: это заявление автора исходных данных,
не независимо проверенное качество. Описание не исполняется как инструкция,
не меняет фильтры, цены, календарь или порядок. Структурированные поля имеют
приоритет над свободным текстом при отборе. Исходные описания могут быть
похожими или расходиться с заполненными полями; это ограничение датасета.

`summary` сообщает число кандидатов и причины исключения. Во внутреннем
`analyzeMatches()` сохраняются все причины каждого отказа, но для итоговых
счётчиков берётся только первая: дата → бюджет → формат → язык → длительность.
Поэтому суммы не дублируют людей. При одном/двух результатах различаются
маленький исходный каталог и исключение остальных кандидатов.

## Ограничения и следующая интеграция

Добавлен необязательный серверный OpenAI-редактор через Responses API. Ключ хранится только в окружении сервера; без ключа, при ошибке или отклонённом ответе используются локальные объяснения. AI не меняет отбор и порядок. Структурные проверки и ссылки на факты не доказывают семантическую истинность любого текста модели. Реальный вызов OpenAI пока не проверен: ключ не настроен; успешные и ошибочные ответы проверены через тестовую подмену HTTP.

Цены и города с imputed-флагами, синтетические профили и ограниченный календарь остаются видимыми ограничениями данных. Не гарантируются итоговые цены или фактическая доступность. В исходном каталоге нет отзывов: ссылки на описание нельзя выдавать за отзывы клиентов.

Файлы интерфейса и README в этой части не изменены. Подключение новых возможностей выполняет участник B по [инструкции](smart-matching.md). Ветки автоматически не объединяются.

## Расширенный «План Б» (23.09.2026)

Поиск альтернативных дат охватывает весь поддерживаемый календарь, сохраняя бюджет и остальные условия. Показываются до двух ближайших дат. Если подходящих дат нет, доступен минимальный бюджет на исходную дату даже при увеличении более 20%; интерфейс прямо помечает существенное изменение. Для нулевого бюджета процент не вычисляется. Каждое предложение меняет ровно одно условие и применяется только по кнопке; совместное изменение даты и бюджета пока не предлагается.

Регрессионный сценарий: Астана, 26.09.2026, свадьба, Ведущий, 400 000 ₸, русский, 6 ч. Основная выдача пустая; предложен бюджет 800 000 ₸ (+100%) для Санджи Виндсмока. Проверены поиск даты за пределами недели, приоритет исходного бюджета, нулевой бюджет и граница 20%. `npm run check` — 51 тест, контроль исходных 66 профилей и браузерного модуля; `npm run build` проходит.
