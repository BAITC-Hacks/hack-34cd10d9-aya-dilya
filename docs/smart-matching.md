# Умный подбор, OpenAI и «План Б» — часть A

## Что готово

Ветка `codex/smart-matching` основана на `codex/integration-check`. Исходные 66 профилей, CSV и подготовленный каталог не изменены. Файлы интерфейса и README сохранены: новые возможности подключает участник B.

`SmartRecommendationRequest.preferences?: string` — необязательные пожелания до 500 символов. Фиксированный словарь распознаёт десять тем: технологии, камерность, тактичность, импровизация, репортаж, джаз, живое исполнение, welcome, персонализация и национальная тематика. Это прозрачная текстовая эвристика, не эмбеддинги и не понимание произвольного текста. Отрицания распознаются частично; неизвестные темы не влияют на порядок. Смешанные пожелания могут быть распознаны не полностью — показывайте `preferenceSummary`.

Сначала применяются все прежние жёсткие фильтры, затем кандидаты сортируются по количеству тем с подтверждающими фрагментами описания, по цене и id. `cards[].evidence` содержит дословные цитаты, `unmatchedPreferences` — распознанные темы без подтверждения. Отсутствие подтверждения не доказывает отсутствие навыка. Названия анонимизированных брендов не считаются доказательством IT-опыта.

`no_match` может содержать `alternatives`: до трёх предложений с готовым новым `request`. Каждое меняет только одно условие:

- Минимальный бюджет на выбранную дату, при котором появится кандидат. Увеличение до 20% показывается рядом с датами. Более существенное увеличение предлагается только когда смена даты не помогает сохранить исходный бюджет; оно явно помечается. Для нулевого бюджета показывается сумма без процента.
- До двух ближайших подходящих дат во всём доступном календаре (23.09–31.12.2026); при равной дистанции сначала будущая дата.

Основная выдача остаётся пустой до явного выбора пользователем. Альтернативы не меняют город, категорию, формат, язык, длительность и пожелания. Совместное ослабление бюджета и даты не производится. При `category_absent` альтернатив нет.

## Сервер и OpenAI

```sh
npm ci
npm run check
npm run dev
```

Vite обслуживает `POST /api/recommend` через серверный middleware. Для запуска собранного приложения с API:

```sh
npm run build
npm run start
```

Адрес: `http://127.0.0.1:4173`. `npm run preview` обслуживает только статику, без API. Требования Node указаны в package.json; серверный запуск требует установленного tsx из devDependencies.

Ключ необязателен. Для включения AI скопируйте `.env.example` в `.env`, заполните `OPENAI_API_KEY` локально и перезапустите сервер. Не используйте префикс `VITE_`, не вставляйте ключ в интерфейс, чат или коммит. `OPENAI_MODEL` по умолчанию `gpt-4.1-mini`; выбранная модель должна поддерживать Responses, Structured Outputs и передаваемые параметры.

Сервер передаёт OpenAI запрос пользователя и факты только о выбранных кандидатах, включая цитаты из описаний. Используются Responses API, `store: false`, строгая JSON-схема, таймаут 6,5 секунды, максимум два одновременных обращения. Успешные результаты кешируются на 15 минут (до 100 записей); одинаковые одновременные запросы объединяются. HTTP API ограничен 30 запросами в минуту на адрес и телом до 8 KiB. Это локальный сервер для хакатона; отдельного пользовательского входа и распределённого ограничения расходов здесь нет.

Модель редактирует только текст. Проверяются идентификаторы, ссылки на доступные факты, числа и некоторые неподтверждённые утверждения (отзывы, рейтинги, обещания доступности). Эти проверки не гарантируют отсутствие любого смыслового искажения. `aiEvidence` содержит факты из каталога, а не сгенерированные ссылки. Пользователю нужно показывать источники и сохранять предупреждения о цене «от» и календаре.

`ai.mode` равен `openai` только после успешной генерации и проверок. Иначе `rules`, причина: `not_configured`, `unavailable` или `invalid_response`. Отсутствие ключа и сбой модели не превращают результат в `no_match`.

Документация API: [Responses и генерация текста](https://developers.openai.com/api/docs/guides/text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Подключение для участника B

Новый `SmartRecommendationRequest` расширяет исходный `RecommendationRequest` необязательным полем `preferences`. Это сохраняет совместимость текущей формы, которая строит поля по ключам базового типа. В сервисе поддерживаются оба варианта; новые поля ответа также необязательны. Для новой формы используйте расширенный тип. `getCatalogOptions()` остаётся синхронным локальным методом. Для AI адаптер должен вызывать `POST /api/recommend` с JSON запроса и `Content-Type: application/json`; сейчас существующий UI использует только локальный core.

Порядок подключения:

1. Добавить необязательное поле пожеланий с ограничением 500 символов; передавать его как `preferences`.
2. В адаптере сначала валидировать запрос локально. Отправить его на `/api/recommend`; при недоступности сервера выполнить локальный `recommend()` и пометить `ai: {mode: 'rules', reason: 'unavailable'}`. Локальные ошибки ввода/сервиса должны оставаться ошибками. Для HTTP 400 показать ошибки полей, не пустую выдачу. Таймаут клиента — больше серверного, например 8,5 секунды. Сохранить защиту от устаревших ответов.
3. Показать `preferenceSummary`, цитаты `evidence` и неподтверждённые пожелания. Для `ai.mode === 'openai'` показать маркировку AI и раскрываемые `aiEvidence`; в остальных случаях — «Объяснение по данным каталога».
4. При `no_match` показывать `alternatives` отдельно от карточек. Отображать изменение бюджета/даты и число кандидатов. Только после нажатия «Применить» заполнить форму из `alternative.request` и выполнить новый запрос. Не подмешивать альтернативы в основные карточки.
5. Импортировать `smartExamples` из `src/data/smart-examples.ts` для двух дополнительных демо. Это реальные запросы, не тестовые ответы.

С `preferences: 'IT-корпоратив'` первым становится Джинбей (HK-75012): в описании есть «технологические форумы». Это тематическая близость, не доказательство работы с IT-компаниями. Итоговые id: HK-75012, HK-88430, HK-44923.

**План Б.** Алматы, 10.10.2026, корпоратив, Ведущий, 480 000 ₸. Основной результат `no_match`, карточек нет. Предложение увеличить бюджет до 500 000 ₸: +20 000 ₸, +4,2%. После применения — HK-88430. Нельзя обещать окончательную стоимость 500 000 ₸: это цена «от».

## Проверки

`npm run check` проверяет данные, типы, 40 тестов и браузерную сборку core. Сохраняются восемь исходных сценариев и проверка 6 600 запросов по всему календарю. Дополнительно проверяются тематические цитаты, отрицания, сохранение ограничений, детерминизм, границы уступок, неизменность исходного запроса и серверный API.

OpenAI проверен через подмену HTTP: успешная генерация, кеш, одновременные запросы, ошибки, отказ, неполный ответ, неизвестные факты и числа. Реальный вызов OpenAI не выполнен: ключ не настроен. Реальный локальный HTTP-запрос без ключа возвращает тематическую выдачу и `rules/not_configured`. UI новых функций ещё не подключён, поэтому его ручная проверка — следующий шаг участника B.
