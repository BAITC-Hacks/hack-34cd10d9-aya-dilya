## OpenAI

Скопировать `.env.example` в `.env`, если файла ещё нет. Заполнить `OPENAI_API_KEY` локально, затем выполнить `npm run check:ai`. Скрипт делает один запрос с тремя выбранными профилями и печатает объяснения с источниками, без ключа. Успех — `ai.mode: openai` и код завершения 0. Без ключа код 2. Если срабатывает резервный режим, код 1: это не успешная проверка AI.

После изменения `.env` перезапустить сервер. На хостинге задать ключ через настройки секретов, а не добавлять `.env` в репозиторий. В релизе без ключа всё работает по правилам каталога.

## Обязательная сдача на платформе

Согласно предоставленной «Инструкции для участников HackAlem AI», итоговый код нужно отправить в GitHub-репозиторий команды, выданный платформой. README должен описывать возможности, технологии, архитектуру, установку, запуск, пример проверки, данные, внешние сервисы и ограничения. Ссылка на развёрнутую версию указывается «если она есть»: Render не является обязательным условием этой инструкции.

После отправки кода на странице треков выбрать свой кейс, нажать «Сдать решение», заполнить название и описание. До дедлайна решение можно обновлять. Один push в GitHub не заменяет сдачу на платформе.

В кейсе требуется работающая проверка, минимум три запроса (плотная категория, редкая категория, пустой результат), повторяемый порядок и изменение выдачи при смене даты. Общая инструкция не устанавливает обязательное выступление команды. Слайды и сценарий выступления в репозитории — дополнительные материалы.

## Размещение на Render

Размещение необязательно и пока не выполнено: Render не получил доступ к приватному репозиторию организации. Локальный запуск и проверка репозитория от этого не зависят.

Если команда решит разместить приложение на Render, нужен **Web Service** с Node.js, поскольку приложение использует серверный API. Один сервис обслуживает UI и API с одного домена.

| Настройка | Значение |
| --- | --- |
| Repository | BAITC-Hacks/hack-34cd10d9-aya-dilya |
| Branch | согласованная финальная ветка, затем main |
| Build Command | `npm ci --include=dev && npm run check && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| HOST | `0.0.0.0` |
| PORT | значение платформы, не переопределять локальным 4173 |
| NODE_VERSION | `22` (ветка 22.x >=22.12) |
| OPENAI_MODEL | `gpt-4.1-mini` |
| OPENAI_API_KEY | необязательный секрет |

`tsx` сейчас находится в devDependencies, поэтому при установке нужен `--include=dev`. Подключить GitHub-репозиторий в кабинете хостинга, выбрать ветку и тариф самостоятельно. Автоматическое размещение лучше выключить на время подготовки защиты. После запуска:

```sh
npm run smoke:release -- https://АДРЕС-ПРИЛОЖЕНИЯ
```

С реальным ключом smoke-проверка может вызвать платную генерацию для двух непустых выдач. Проверить также оба демосценария в браузере по опубликованной ссылке. Если публичный URL ещё не создан, локальный адрес нельзя выдавать жюри как ссылку на размещённое приложение.

Основание настроек: [Render Web Services](https://render.com/docs/web-services). Приложение должно слушать `0.0.0.0` и назначенный `PORT`. Health не вызывает OpenAI и проверяет наличие собранной страницы.

Текущий rate limit использует адрес непосредственного соединения. За прокси запросы могут делить лимит 30/минуту. Для хакатонного демо это консервативная общая защита. Перед массовым запуском понадобятся проверенная схема доверия прокси, идентификация пользователей и контроль расходов.
