# Firebird

MVP команды Aya & Dilya: русскоязычный интерфейс подбирает до трёх event-подрядчиков по городу, дате, формату, категории и бюджету в тенге. Язык, длительность и пожелания до 500 символов необязательны.

## Запуск

Нужны Node.js 20.19+ в ветке 20.x или Node.js 22.12+ и npm.

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

Откройте адрес, напечатанный Vite (обычно http://127.0.0.1:5173). Проверки и сборка:

```sh
npm run check
npm run build
npm run start
```

`npm run check` проверяет актуальность данных, TypeScript, все 49 тестов ядра, сервера и UI-адаптера и браузерную сборку сервиса. `npm run build` собирает полное приложение.

## Что работает

- Форма получает справочники через `getCatalogOptions()`; даты ограничены календарём 23.09–31.12.2026.
- Адаптер `src/pages/recommendationServiceAdapter.ts` проверяет ввод валидатором A и вызывает `POST /api/recommend`. Справочники остаются локальными. При недоступности API или таймауте 8,5 секунды выполняется локальный подбор с явной отметкой; ошибки полей HTTP 400 показываются у формы.
- Пожелания передаются сервису без фильтрации и ранжирования в UI. Показываются `preferenceSummary`, дословные цитаты `evidence` и темы без подтверждения.
- Режим `openai` маркируется как AI с раскрываемыми фактами `aiEvidence`; режим `rules` — «Объяснение по данным каталога». Без настроенного ключа работает подбор по правилам.
- «План Б» отдельно предлагает изменения бюджета или даты и число кандидатов. Только кнопка «Применить» заполняет форму из готового запроса сервиса и запускает новый подбор. Если форма уже отредактирована, показано предупреждение о замене её полей.
- Карточки показывают имя, категорию, город, цену «от», готовое `explanation` сервиса и календарную доступность. Над результатом выводится `summary` без пересказа со стороны UI.
- `synthetic`, `cityImputed`, `priceImputed` показаны независимыми русскоязычными метками.
- Есть состояния загрузки, 1–3 результатов, отсутствующей категории, пустой выдачи, ошибок ввода и технических ошибок с повтором.
- Рядом с результатом сохраняется снимок отправленных условий. Редактирование формы не меняет старый результат; интерфейс предлагает повторить подбор. Устаревшие ответы и ошибки игнорируются.
- Примеры из `src/data/demo-queries.json` и `src/data/smart-examples.ts` только заполняют форму. Нажатие кнопки вызывает настоящий сервис, заранее подготовленных ответов в продукте нет.
- Интерфейс адаптируется к мобильной ширине, поддерживает клавиатуру, подписи полей и объявления статуса.

Подбор по этому каталогу не означает проверку реального подрядчика. Синтетические профили и оценочные город/цена помечены. «По календарю не занят» означает отсутствие занятости в данных на выбранную дату; это не подтверждённая доступность. Начальная цена не является итоговой сметой. Параметры не ослабляются автоматически.

Бронирования, оплаты, регистрации и отправки сообщений нет. Сайт не опубликован.

## Интеграция A и B

Ветка B: `codex/recommendation-ui`. Часть A обновлена до `origin/codex/smart-matching`, `b645207`; прежний UI и документация сохранены. Новые серверные файлы, контракт и зависимости пришли из ветки A. Общий контракт, `src/core`, `src/data`, `scripts`, тесты ядра, зависимости и конфигурация TypeScript не изменялись участником B.

Точка входа UI — `index.html` → `src/main.tsx` → `src/pages/RecommendationPage.tsx`. Дополнительные зависимости не нужны. Для подключения к другой ветке сначала убедитесь, что в ней есть коммит A `b645207`, затем перенесите отдельный UI-коммит B. Хеш UI-коммита указан в сообщении о сдаче; все предыдущие файлы интерфейса уже входят в b645207. Альтернативно перенесите готовую ветку B после проверки её diff. Автоматического слияния в main не выполнялось.

## Серверный запуск и новые сценарии

`npm run dev` обслуживает и UI, и API. Для собранного приложения используйте `npm run build` и `npm run start`, адрес http://127.0.0.1:4173. `npm run preview` не включает API и приводит к локальному резервному подбору.

Настройка необязательного серверного AI описана в [docs/smart-matching.md](docs/smart-matching.md). Ключи не передаются браузеру. При настроенном AI запрос и факты выбранных профилей отправляются сервером OpenAI; без ключа API возвращает объяснения по правилам. Реальный вызов модели в этой интеграции не проверялся — ключ не настраивали.

Проверено после подключения smart-matching: `npm ci --offline`, `npm run check` (49 тестов), production build. В браузере IT-пожелание возвращает HK-75012 первым с цитатой о технологических форумах; «План Б» сохраняет бюджет 480 000 до нажатия кнопки и возвращает HK-88430 после изменения до 500 000. Проверены альтернативные даты. HTTP-адаптер покрыт тестами ошибок ввода, сбоя сети/API, таймаута, сохранения AI-метаданных и пожеланий. Цитаты выводятся как текст, включая HTML-подобные строки.
